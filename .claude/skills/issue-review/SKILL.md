あなたはissue駆動開発ワークフローのレビューフェーズを担うエージェントです。2つの独立したサブエージェントを起動してレビューを実施し、Critical/Importantが0件の場合のみReview PassedをissueにコメントしてPR作成を許可します。

**このスキルのReview Passedコメントなしに `m11n:issue-pr` はPRを作成しません。**

## 動的コンテキスト

### 現在のブランチと最新コミット

### リポジトリ情報

!`gh repo view --json nameWithOwner,url --jq '"- リポジトリ: \(.nameWithOwner)\n- URL: \(.url)"' 2>/dev/null || echo "(リポジトリ情報を取得できませんでした)"`

## ワークフロー

### Step 1: 入力パース

`$ARGUMENTS` からissue番号を抽出する:
- `#123` 形式 → `123`
- `https://github.com/org/repo/issues/123` 形式 → `123`
- 数字のみ → そのまま使用

### Step 2: Design Workpad の読み込み

issueコメントからDesign Workpadを取得して受入基準を把握する:

```bash
gh issue view <番号> --json comments --jq '.comments[].body' | grep -A 100 "m11n:state:workpad"
```

Workpadが存在しない場合は**即座に停止**:
```
Design Workpadが見つかりません。
先に `/m11n:issue-design #<番号>` を実行してください。
```

### Step 3: 差分の取得

レビュー対象の変更差分を取得する:

```bash
# デフォルトブランチとの差分
git diff $(git symbolic-ref refs/remotes/origin/HEAD | sed 's|refs/remotes/origin/||')...HEAD --stat
git diff $(git symbolic-ref refs/remotes/origin/HEAD | sed 's|refs/remotes/origin/||')...HEAD
```

### Step 4: Spec Compliance Review（サブエージェント）

`spec-reviewer-prompt.md` の指示に従ってサブエージェントを起動する。
サブエージェントにはWorkpadの受入基準と実装差分を渡す。

サブエージェントの指示内容は `spec-reviewer-prompt.md` を参照。

### Step 5: Code Quality Review（サブエージェント）

`quality-reviewer-prompt.md` の指示に従ってサブエージェントを起動する。
サブエージェントには実装差分を渡す。

サブエージェントの指示内容は `quality-reviewer-prompt.md` を参照。

### Step 6: 結果の統合と判定

両サブエージェントの結果を統合して以下の判定を行う:

**通過条件**: Spec Compliance・Code Quality ともに Critical/Important が **0件**

#### 通過した場合

現在のコミットハッシュを取得してReview Passedコメントを投稿する:

```bash
COMMIT=$(git rev-parse --short HEAD)
gh issue comment <番号> --body "$(cat <<'EOF'
<!-- m11n:state:review-passed -->
## Review Passed

- Spec Compliance: ✅ 受入基準をすべて満たしています
- Code Quality: ✅ Critical/Importantな問題はありません
- Reviewed at commit: ${COMMIT}

---
*Generated by m11n:issue-review*
EOF
)"
```

完了報告:
```
レビューが通過しました。

次のステップ: `/m11n:issue-pr #<番号>` でドラフトPRを作成できます。
```

#### 通過しなかった場合

検出された問題をユーザーに提示する:

```
## レビュー結果: 要修正

### Spec Compliance
[問題があれば記載]

### Code Quality
[Critical/Important の一覧]

修正後、再度 `/m11n:issue-review #<番号>` を実行してください。
```

**Review Passedコメントは投稿しない。** `m11n:issue-implement` で修正 → 再度このスキルを実行するよう案内する。

---

## Integration Points

- **前**: `m11n:issue-implement` で実装が完了していること
- **後**: `m11n:issue-pr` はこのスキルのReview Passedコメントをゲートとして確認する
- **再実行**: `m11n:issue-implement` が再実行されると `review-invalidated` が投稿されるため、その後は再度このスキルを実行する必要がある

---

## エラーハンドリング

| エラー | 対応 |
|--------|------|
| Workpadが存在しない | issue-designの実行を案内して終了 |
| 差分が空 | コミットがない旨を報告し、issue-implementの実行を案内 |
| サブエージェントのレビューに失敗 | エラー内容を表示し、手動レビューを促す |
| コメント投稿失敗 | エラー内容を表示し、手動でコメント内容を提示 |
